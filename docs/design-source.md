# WOONG HUB — 개인 통합 대시보드 구축 설계안

(설계 v1.0) 2026.11.17 · 하이브리드형 · PC + 모바일

이번 사이트는 **매일 사용하는 개인 포털 + 취미별 전문 관리 시스템**으로 설계하는 게 좋겠어.

단순히 여러 웹사이트의 정보를 모으는 것에서 끝나는 게 아니라, 시간이 지날수록 내 데이터가 쌓이고 개인화되는 사이트를 목표로 하자.

최종적으로는 다음 네 가지를 만족하는 구조야.

- **정보 확인\:** 날씨, 일정, 뉴스, 관심 분야 업데이트
- **취미 관리\:** 오디오 장비, 게임, 음악, PC 하드웨어
- **생활 관리\:** 할 일, 메모, 북마크, 위시리스트, 알림
- **자동화\:** 뉴스 수집, AI 요약, 정기 브리핑, 가격·일정 알림

## 2\. 사이트 전체 메뉴와 화면 설계

**메인 메뉴**

### A. 홈 — `/`

사이트를 열면 가장 먼저 보는 화면이야.

필수 위젯

| 위젯 | 표시 정보 | 주요 동작 |
|--------|--------|--------|
| 날씨 | 현재 기온, 체감온도, 강수 확률, 미세먼지 | 시간별·주간 예보 |
| 일정 | 오늘·내일 일정, 다음 예정 | 일정 상세 열기 |
| 할 일 | 오늘 마감, 진행 중 | 즉시 완료 처리 |
| 뉴스 | 분야별 핵심 뉴스 3\~5개 | 기사·브리핑 열기 |
| 관심사 | 오디오·게임의 새 소식 | 해당 허브 이동 |
| 즐겨찾기 | 자주 쓰는 사이트 | 새 탭 열기 |
| 통합 검색 | 저장한 자료 및 사이트 데이터 | 통합 결과 보기 |

처음에는 고정 레이아웃으로 만들고, 이후 사용자별로 위젯을 드래그해서 배치하도록 확장하자.

구현할 핵심 기능은 다음과 같아.

- 기존 6개 뉴스 분야 유지, 세부 카테고리 확장
- 신규 기사 주기적 수집, 중복 기사 제거
- 기사별 AI 요약 및 중요한 이유 설명
- 오전 8시 종합 브리핑과 날짜별 보관
- 읽음·안 읽음·스크랩·관심 없음 표시
- 키워드 추적 및 관심도 기반 우선순위 정렬
- 수동 새로고침과 마지막 업데이트 시간 표시

기사 데이터는 `제목 + 출처 + 발행시간 + 원문 URL + 요약` 중심으로 저장하고, 원문을 무단 복제하지 않는 구조가 좋아.

**기존 뉴스 사이트의 API, DB, 소스코드에 접근 가능한지는 아직 확인하지 못했어.** 따라서 이식 여부는 해당 프로젝트 구조를 확인한 뒤 결정해야 해.

### E. 음악 허브 — `/music`

음악은 음악 재생기를 처음부터 만드는 것보다 **음악 컬렉션과 발견 기능** 중심으로 시작하는 게 합리적이야.

| 기능 | 구체적인 내용 |
|--------|--------|
| 내 컬렉션 | 보유 FLAC·CD·디지털 앨범 목록 |
| 앨범 상세 | 아티스트, 발매일, 장르, 포맷, 메모 |
| 신보 추적 | 관심 아티스트의 신곡·앨범 출시 |

| 음악 위시리스트 | 구매하고 싶은 앨범·음반 |
| 외부 연결 | Apple Music·Spotify 열기 |

향후에는 로컬 음원 파일의 메타데이터를 읽어서 앨범 목록을 일괄 등록하는 기능도 추가할 수 있어. 처음부터 음원 파일 자체를 서버에 업로드할 필요는 없어.

### F. 캘린더·생활 허브 — `/calendar`, `/library`

캘린더는 Google Calendar를 주 일정 데이터로 사용하고, 자체 할 일 목록을 별도 저장하는 방식이 좋아.

캘린더는 첫 버전에서 **읽기 전용 연동**으로 시작하고, 안정화 후 일정 생성·수정 권한을 추가하자. Google은 기능에 필요한 최소 OAuth 권한을 요청하도록 권장하고 있어. citeturn819272search5

라이브러리는 개인 데이터 저장소 역할을 해.

- 빠른 메모와 체크리스트
- 폴더·태그별 북마크 정리
- 구매 위시리스트와 가격 메모
- 할 일 및 개인 프로젝트 목록
- 관심 주제별 저장 기사
- 모든 기록을 검색하는 통합 검색

### G. 업무 허브 — `/work`

업무 데이터는 홈에 지나치게 많이 노출하지 않고 **선택적 독립 영역**으로 만들자.

기존 스토어 인사이트 웹사이트를 열 수 있는 바로가기부터 제공하고, 이후 필요하면 매출·광고비·ROAS·주요 판매처 현황을 API로 연동하는 방식이야.

업무용 데이터에는 별도 접근 권한을 설정하고, 개인 취미 데이터와 분리하는 걸 권장해.

## 3\. 실제 개발에 사용할 기술 구조

**완전히 독립적으로 운영할 수 있는 웹앱**으로 만드는 걸 추천해. ChatGPT나 다른 AI 개발 도구를 바꾸더라도 소스코드와 데이터베이스를 유지할 수 있도록 하는 게 중요해.

**사용자 화면**

PC 브라우저 / iPhone PWA

**Next.js 웹 애플리케이션**

React · TypeScript · Tailwind CSS · shadcn/ui

화면 구성 / 로그인 검증 / 서버 API

**Supabase**

PostgreSQL 데이터베이스

사용자 인증 · 개인 데이터 · 파일

**자동화 워커**

뉴스 수집 · AI 요약

정기 실행 · 알림 생성

**외부 데이터 연결**

Next.js App Router는 페이지와 공통 레이아웃을 나누기 편하고, Supabase는 인증과 DB 접근 제어를 제공하므로 이런 종류의 개인 웹앱에 잘 맞아. citeturn819272search0turn819272search13turn772893search11

## 4\. 데이터베이스 구조

나중에 장비, 뉴스, 게임 등 데이터가 늘어나는 걸 고려해 처음부터 분리해두는 게 좋겠어.

| 테이블 | 저장 내용 |
|--------|--------|
| `profiles` | 사용자 기본 정보, 설정 |
| `dashboard_widgets` | 위젯 위치, 크기, 표시 여부 |
| `integrations` | 연결된 외부 서비스의 상태와 권한 |
| `todos` | 할 일, 우선순위, 마감일 |
| `notes` | 개인 메모, 태그 |
| `bookmarks` | URL, 폴더, 즐겨찾기 |
| `news_articles` | 기사 원본 정보, AI 요약, 중복 그룹 |
| `news_user_states` | 기사 읽음, 스크랩, 숨김 상태 |
| `audio_gear` | 보유·판매·관심 오디오 장비 |
| `audio_setups` | 장비 연결 조합과 평가 |
| `games` / `user_games` | 게임 정보 및 개인 플레이 기록 |
| `music_albums` | 음악 컬렉션, 평가 |
| `wishlist_items` | 구매 관심 상품 |
| `notification_rules` | 알림 조건 |
| `sync_jobs` | 자동 수집 실행 기록과 오류 |

개인 데이터 테이블에는 `user_id`를 두고, 사용자가 자신의 데이터에만 접근하도록 설정할 거야.

OAuth 토큰, API 키 같은 민감한 정보는 일반 테이블에 평문으로 저장하거나 브라우저에 노출하지 않아야 해.

| 데이터 | 권장 주기 | 처리 방식 |

| 일정 | 5\~15분 또는 접속 시 | Google Calendar 조회 |

| Steam 정보 | 하루 1회 또는 수동 | 접근 가능한 데이터 동기화 |
| 가격 알림 | 하루 1\~2회 | 지원되는 가격 소스 비교 |
| 개인 메모·할 일 | 변경 즉시 | DB 저장 |

이 주기는 추천 설정값이고, 서비스별 API 제한과 운영 비용에 맞춰 조절하면 돼.

### 뉴스 처리 흐름

여기서 중요한 건 AI 요약을 페이지를 열 때마다 다시 생성하지 않는 거야. **신규 기사를 저장할 때 한 번 생성하고 재사용하는 방식**이 비용과 속도 면에서 유리해.

또한 현재 ChatGPT에서 받는 브리핑이 새 사이트에 자동으로 전달되는 것은 아니므로, 사이트 전용 수집·브리핑 작업을 별도로 구현해야 해.
