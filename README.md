# WOONG HUB

일정, 할 일, 날씨, 메모를 한눈에 보고 작품·오디오·게임·음악 컬렉션을 관리하는 개인 대시보드입니다. 맨시티 경기와 EPL 순위표를 보거나 Notion·Google 캘린더, Spotify, Steam을 연결할 수 있습니다.

운영 중인 [WOONG HUB](https://woong-personal-hub.woong22222.chatgpt.site/)는 소유자 전용입니다. 개발용 미리보기는 아래 실행 절차로 열 수 있습니다.

## 홈에서 자주 하는 일

- **오늘 확인하기** — 다음 일정과 오늘 할 일을 먼저 보고, 주간 일정에서 날짜를 눌러 그날의 일정을 펼칩니다.
- **날씨 확인하기** — 홈에서 현재 기온과 강수 요약을 보고 ‘예보’를 펼쳐 시간별 24시간과 일별 7일 예보를 확인합니다. 기본 지역은 수원이며, 예보를 펼친 화면에서 전국 41개 도시 중 하나를 선택할 수 있습니다. Open-Meteo는 강수 확률을 표시합니다. 대체 제공처인 MET Norway는 확률 값이 없을 때 제공되는 시간별 예상 강수량(mm)을 표시합니다.
- **메모 쓰기** — 홈의 ‘메모 쓰기’나 기록 메뉴에서 제목과 본문을 입력합니다. ‘분류 및 링크’를 펼치면 추가 정보를 입력할 수 있습니다. 모바일에서는 편집기가 전체 화면으로 열리고, 작성 중인 초안은 해당 기기에 보관됩니다. ‘완료’를 누르면 메모를 저장합니다.
- **홈 맞춤 설정** — ‘오늘’ 옆 위젯 설정에서 표시할 항목과 하단 위젯 순서를 고릅니다. 모바일 하단에는 홈·일정·취미·기록·더보기가 한 줄에 표시됩니다.
- **취미 이어서 보기** — ‘취미’에서 작품 보관함, 축구, 음악, 게임, 오디오를 엽니다. 홈의 ‘이어서 하기’에서 보던 작품을 열고, ‘맨시티 다음 경기’에서 한국 시간으로 킥오프를 확인합니다.
- **연결 상태 확인하기** — 설정 → 연결 관리에서 Spotify 승인 권한, Steam 계정과 최근 조회, Notion·Google 캘린더 반영 상태를 확인합니다.

## 실행

Node.js 24 이상, pnpm 11.25.0을 사용합니다. 미리보기는 운영 DB와 분리된 SQLite DB를 사용합니다.

```powershell
pnpm install
pnpm check
pnpm test
pnpm build
pnpm preview
```

`http://127.0.0.1:3000`에서 확인합니다. `pnpm dev`도 같은 빌드 결과를 제공하며 변경 후에는 다시 빌드해야 합니다. 개발 서버가 넣는 `local-preview-owner`는 로컬에서만 사용하고 배포 파일에 포함하지 않습니다. DB와 테스트 기록은 무시된 `.sites-runtime/local.sqlite`에 있습니다.

화면은 Next.js App Router + React + TypeScript이며 `out/`으로 내보냅니다. 빌드 스크립트가 화면 자산과 API를 하나의 Cloudflare Worker 모듈인 `dist/server/index.js`로 묶습니다. Sites의 기존 프로젝트 ID와 소유자 전용 접근을 유지하며, `.openai/hosting.json`의 `d1: "DB"`로 운영 DB를 연결합니다. 이 버전부터 정적 전용 배포로는 API가 작동하지 않습니다.

## 구현 범위

- PC 상단 메뉴와 모바일 하단 한 줄 메뉴, 화면 폭에 맞춰 재배치되는 홈 카드
- 다크/라이트 테마, 홈 위젯 표시와 하단 위젯 순서 설정
- Open-Meteo 날씨 요약, 시간별·일별 예보, MET Norway 대체 예보
- 한국 시간대 날짜, 월 이동 캘린더, 직접 일정 등록
- 할 일·메모·북마크·오디오·게임·앨범·작품·업무 기록 추가/수정/삭제
- 맨시티 다음 경기와 예정 경기, EPL 20팀 순위표와 최근 리그 결과
- 통합 검색, 할 일 완료 처리, 일정 알림 목록
- 로그인 계정별 서버 저장, 15초 간격 및 화면 복귀 시 동기화
- 동시 변경 버전 검사와 충돌 시 사본 보존
- 기기별·탭별 보류 변경 보관, 오프라인 변경 재전송, 저장 상태 표시
- 이전 브라우저 기록의 병합 이전 및 원본 보존
- 검증을 거친 JSON 가져오기/내보내기
- 관심 뉴스와 전체 최신 기사, 주제 팔로우, 분야·검색·날짜 필터, 읽음·스크랩·숨김과 계정별 저장
- 홈의 실제 기사 미리보기, IEM Atlas·스토어 인사이트 바로가기
- 모바일 설치용 웹 앱 매니페스트 (오프라인 실행과 푸시는 미구현)

## 작품 보관함과 TMDB 검색

1. **취미 → 작품 보관함 → 작품 추가**에서 영화·드라마·웹툰을 선택한 뒤 제목과 감상 상태를 저장합니다. 감상 상태는 ‘볼 예정’, ‘보는 중’, ‘완료’ 중 하나를 고릅니다.
2. 영화는 ‘감상 완료’, 드라마와 웹툰은 ‘다음 회차’ 버튼으로 진행도를 갱신합니다. 드라마는 시즌을, 웹툰은 연재 요일을 지정할 수 있습니다. 별점·작품 링크·감상 메모도 함께 저장합니다.
3. 홈의 ‘이어서 하기’에는 최근에 수정한 ‘보는 중’ 작품을 표시합니다. 웹툰의 오늘 연재 예정 목록은 직접 등록한 연재 요일과 한국 표준시(KST)를 기준으로 표시합니다. 작품 기록은 다른 HUB 기록과 함께 동기화되고 JSON 백업에 포함됩니다.

### 운영 사이트의 TMDB 설정

1. [TMDB API 설정](https://www.themoviedb.org/settings/api)에서 API 사용을 신청하고 **API Read Access Token**을 복사합니다. [TMDB 인증 안내](https://developer.themoviedb.org/docs/authentication-application)
2. [ChatGPT Sites](https://chatgpt.com/sites)에서 **WOONG HUB → ⋯ → 설정**을 열고 환경 변수 및 시크릿에 `TMDB_READ_TOKEN`을 **시크릿**으로 추가합니다. 값 입력란에는 복사한 토큰 그대로 넣습니다. [Sites 설정 안내](https://learn.chatgpt.com/docs/sites/managing-a-site#configure-runtime-environment-values)
3. 시크릿을 저장한 뒤 사이트의 저장 버전을 재배포합니다. **작품 추가 → 영화 또는 드라마 → 제목 입력 → TMDB 검색**에서 결과를 선택하면 제목과 제공된 포스터·공개 연도를 가져옵니다. ‘저장하기’를 누르면 보관함에 추가됩니다. [시크릿 반영 안내](https://help.openai.com/en/articles/20001339-creating-and-using-chatgpt-sites)

TMDB는 운영 사이트의 선택 연동입니다. 기본 로컬 미리보기와 TMDB 미연결 상태에서도 작품 직접 등록과 감상 기록을 사용할 수 있습니다.

## 맨시티 경기 일정과 EPL 순위표

- 홈에서는 맨시티 남자팀의 다음 경기 한 건을 한국 시간으로 확인합니다. **취미 → 축구 → 맨시티 일정**에서 대회명·경기장과 예정 경기를 봅니다. 일정과 킥오프 시간은 [맨시티 공식 캘린더](https://www.mancity.com/calendars/mens)를 사용합니다.
- **EPL 순위표**는 20팀 중 맨시티 행을 강조하고, **최근 EPL 결과**는 맨시티의 최근 리그 경기 최대 5건을 표시합니다. 두 항목은 [OpenLigaDB](https://www.openligadb.de/) 커뮤니티 집계이며 화면에서 조회 시각과 공식 사이트 링크를 확인할 수 있습니다.
- 서버는 조회한 축구 데이터를 15분간 최신으로 취급합니다. 이후 원본 조회가 실패하면 저장된 데이터가 있는 항목은 ‘마지막 조회’ 시각과 함께 표시합니다.

## 저장과 연결 상태

기록과 설정은 **Sites D1 DB의 사용자별 문서**에 저장합니다. 기존 ChatGPT 로그인을 사용하며 별도 Supabase 계정이나 API 키는 필요하지 않습니다. API는 플랫폼이 주입한 사용자 ID로만 문서를 읽고, 쓰기 요청은 동일 출처와 JSON 형식을 검사합니다.

한 번의 저장은 사용자별 문서 전체에 대해 버전을 비교하고 갱신합니다. 다른 기기의 변경이 먼저 저장되면 최신 문서를 받아 세 방향으로 합칩니다. 서로 다른 기록은 합쳐지고, 동일 기록 동시 수정은 사본으로 남깁니다. 삭제와 수정이 충돌하면 수정 내용을 우선 보존하므로 사용자가 사본을 확인해야 할 수 있습니다. 첫 버전의 문서 크기는 사용자당 1MB로 제한합니다.

화면에서 변경하면 먼저 계정·탭별 보류 기록을 브라우저에 보관하고 서버 저장을 확인합니다. ‘서버 저장 완료’ 전에는 브라우저 데이터를 지우지 마세요. 오프라인 최초 접속이나 완전한 오프라인 앱 실행은 제공하지 않습니다. 재접속하면 남은 보류 기록을 복구합니다. 서버 저장이 완료된 기록은 기기 캐시를 지워도 다시 로그인해 불러올 수 있습니다.

이전 `woong-hub:v1` 데이터가 있으면 ‘이전 기록 백업’과 ‘서버로 옮기기’를 표시합니다. 이전 원본을 삭제하지 않으며, 현재 서버 기록과 합쳐 옮깁니다. JSON 백업 내보내기는 현재 화면의 보류 변경도 포함합니다. 파일 가져오기는 현재 기록을 교체하므로 확인 창을 제공합니다.

DB 스키마는 `db/schema.ts`, 생성된 마이그레이션은 `drizzle/`에 보관합니다. 스키마 변경 시 `pnpm db:generate`로 새 SQL을 생성하고 검토합니다. 로컬 미리보기는 시작 시 미적용 SQL만 적용하고, 운영 마이그레이션은 Sites 배포가 적용합니다. 사용자 데이터는 SQL 마이그레이션에 넣지 않습니다.

캘린더는 아래 설명처럼 요청 시 반영합니다. 날씨는 서버에서 Open-Meteo를 우선 조회하고, 실패하면 MET Norway 예보를 사용합니다. 서버 연결도 실패하면 브라우저에서 Open-Meteo를 직접 조회합니다. 폰트 실패 시 시스템 한국어 글꼴로 대체됩니다.

## 뉴스

- **관심 뉴스**는 기본 화면입니다. 팔로우한 게임과 국내 게임 행사, 오디오, 음악, 영화·드라마, 웹툰, 맨시티·EPL, PC 하드웨어가 기본 주제입니다. 분야와 기사 유형을 함께 맞춘 소식에 추천 이유를 표시합니다. 홈은 관심 뉴스 3건을 표시합니다.
- **관심 설정**에서 새 주제와 한글·영문 별칭을 추가하고, 출시·패치나 연재·완결 같은 기사 유형을 선택합니다. 내 게임을 직접 추가하면 연결된 Steam App ID로 한국어 공식 공지를 요청합니다. 최대 20개 주제와 Steam 공지 8개를 팔로우할 수 있습니다.
- ‘이 주제 덜 보기’는 관심 뉴스에 적용됩니다. 관심 설정에서 다시 팔로우할 수 있습니다. ‘기사 숨기기’는 기사 한 건에 적용되며 필터의 ‘숨긴 기사 보기’에서 해제합니다.
- 관심 뉴스는 최근 30일을 기본으로 조회합니다. 제목과 발행 시각이 가까운 보도는 한 카드에 묶고, 같은 소식의 공식 원문이 있으면 앞에 표시합니다. ‘전체 최신’은 수집 기사를 발행일순으로 보여주며 검색·분야·날짜·안 읽음 필터를 지원합니다.
- **한국어로 작성된 글**을 수집합니다. RSS의 제목과 소개에서 한국어를 확인하며, 영어 전용 피드와 영상 채널은 수집 대상에서 제외합니다. 관심 뉴스와 전체 최신은 한국어 글로 표시하고, 예전에 저장한 자료는 스크랩에서 열 수 있습니다.
- 게임·하드웨어는 인벤, 게임동아, 루리웹 게임 뉴스, 보드나라, IT동아 등을 사용합니다. 게임메카는 [공식 RSS](https://www.gamemeca.com/rss.php)에서 제목, 발행일, 짧은 소개와 원문 링크를 읽습니다. 이전에 스크랩한 게임메카 링크도 스크랩에서 열 수 있습니다.
- 디스이즈게임·퀘이사존과 맨체스터 시티 한국어 사이트는 Google 뉴스 공개 RSS에서 출처가 일치하는 소식을 가져옵니다. 퀘이사존은 하드웨어 뉴스 게시판에 해당하는 글만 선별합니다.
- 오디오는 오디오플래닛, 셰에라자드, 영디비를, 음악은 온음, 웨이브 [weiv], VISLA 음악을 읽습니다.
- 영화·드라마는 씨네플레이, 무비프레스, 익스트림무비 영화수다를, 웹툰은 웹툰가이드 공개 뉴스 목록을 사용합니다. 웹툰가이드는 제목·발행일·기사 링크를 읽으며 발행일만 표시합니다.
- 축구는 풋볼리스트와 포포투 코리아를, 해외 일반 뉴스는 연합뉴스 국제 RSS를 사용합니다. 영디비와 익스트림무비는 Google 뉴스에 배포된 게시판 글 중 오디오·영화 소식과 맞는 제목을 수집합니다.
- 마지막 확인 후 1시간이 지나면 페이지를 열 때 갱신합니다. ‘새 기사 확인’은 60초 간격과 동시 실행 제한을 적용합니다. 수집 출처에서 출처별 연결과 마지막 성공 시각을 확인할 수 있으며, 수집 시간 안에 응답한 출처의 기사를 저장합니다. 소개는 출처의 짧은 소개나 런칭 캘린더의 공개 정보입니다.
- `news_articles`는 수집 기사, `news_user_states`는 계정별 읽음·스크랩·숨김, `news_preferences`는 계정별 팔로우 규칙, `news_sync`는 수집 상태입니다. ‘스크랩 백업’은 저장 기사 최신 1,000건을 JSON으로 내보냅니다.

## Notion · Google 캘린더

- 사용자가 고른 Notion 캘린더와 Google 캘린더를 원본 수정 없이 읽기 전용으로 반영합니다. 자동 작업은 만들지 않으며, 이 채팅에 ‘캘린더 일정 다시 반영해줘’라고 요청하면 갱신합니다.
- 월간 달력, 날짜별 일정, 종일·기간·시간 지정 일정, KST 표시와 원본 열기를 제공합니다. 직접 등록한 HUB 일정도 함께 표시합니다.
- 출처별 스위치와 모두 켜기·끄기로 표시를 선택합니다. 설정은 계정별로 동기화하고 백업에 포함합니다. 표시를 꺼도 반영본과 원본 일정은 삭제하지 않습니다.
- 홈의 다음 일정과 주간 일정에도 같은 표시 설정을 적용합니다. 외부 반영본의 마지막 반영 시각과 조회 기간을 표시하며, 기간 밖에는 누락 가능성을 안내합니다.
- ‘반영 내역 새로고침’은 저장된 반영본을 다시 읽습니다. 웹사이트가 제공자의 새 일정을 직접 조회하거나 자동 동기화하는 기능은 아닙니다.
- 캘린더 자료는 소유자 전용 Site의 서버 반영본으로 보관합니다. 소스·공개 GitHub·빌드 산출물에는 실제 일정이나 출처 ID를 넣지 않습니다. 개인 HUB 백업은 표시 설정과 직접 일정만 포함하고 외부 반영본은 포함하지 않습니다.
- 운영 반영 절차는 docs/calendar-update.md에 있습니다. Site를 다른 사람에게 공유하거나 공개하기 전에 반영본의 접근 설계를 다시 확인해야 합니다.

## 오디오 컬렉션과 청음 조합

- 장비 이름, 분류·상태, 제조사·모델, 구매일·구매가(원), 연결·출력, 소리 성향, 청음·사용 메모를 기록합니다.
- 장비와 조합을 별도 목록으로 보고 검색·분류·상태 필터, 최근 등록순·이름순 정렬을 사용합니다.
- 조합은 등록 장비 1~12개를 선택하고 위·아래 버튼으로 연결 순서를 정합니다. 전기적 호환성을 자동 판단하지 않습니다.
- 장비 삭제 시 조합을 함께 삭제하지 않습니다. 남은 연결은 찾을 수 없는 장비로 표시하고 조합 수정에서 바꿀 수 있습니다.
- 보유 구매가 합계는 구매가를 직접 기록한 보유 장비만 포함하며, 가격 입력 수를 함께 표시합니다. 미입력과 0원은 다르게 처리합니다.
- 기존 장비 메모를 유지하고 선택적 `audio` 상세 필드만 더합니다. 기존 JSON 문서와 같은 사용자별 저장·충돌 보존·오프라인 보류·백업을 사용하며 추가 DB 마이그레이션은 없습니다.
- 제품 사양, 가격, 보유 장비를 외부에서 자동 생성하지 않습니다. 새 컬렉션은 빈 상태로 시작합니다.

## 게임 라이브러리와 Steam 상점 정보

- 게임별 플랫폼·상태, 직접 기록한 플레이 시간, 0~5점 별점(0.5점 단위), 시작일·완료일, 최대 8개 태그와 감상 메모를 보관합니다.
- Steam 상점 URL 또는 App ID를 입력해 제목·제작사·배급사·장르·출시 표시·짧은 소개·커버를 확인한 뒤 적용합니다. 기존 제목·관련 링크·메모를 유지하고 빈 제목과 링크만 채웁니다. 저장 전 미리보기를 제공합니다.
- 상점 정보는 게임·DLC 공개 응답만 사용합니다. 계정별 보유 게임·플레이 시간 연결은 아래 Steam 계정 기능으로 제공합니다. 상점 조회가 실패해도 직접 입력할 수 있으며 가격 조회는 제공하지 않습니다.
- 서버는 고정 Steam 상점 주소만 요청하고 인증된 방문자에게만 결과를 반환합니다. 공개 메타데이터만 최대 24시간 캐시하며, 확인일을 표시합니다. 개인 기록·쿠키·사용자 신원은 Steam이나 공개 캐시에 전달하지 않습니다.
- 검색·플랫폼·상태 필터와 최근 등록순·이름순·플레이 시간순·별점순 정렬을 제공합니다. 미입력과 0분·0점은 구분합니다.
- 기존 게임 기록은 그대로 보존하고 선택적인 game 상세 필드만 추가합니다. 같은 사용자별 저장·충돌 사본·오프라인 복구·JSON 백업을 사용하며 추가 DB 마이그레이션은 없습니다.
- 상점 응답은 공개 조회 가능 여부와 제공자 변경·제한에 따라 실패할 수 있습니다. 마지막으로 저장한 상점 정보와 직접 기록한 플레이 내용은 유지합니다.

## 음악 컬렉션과 앨범 검색

- 앨범명·아티스트·포맷·상태, 직접 기록한 장르·발매일/연도·반점 별점·최근 감상일·좋아하는 곡·태그·감상을 저장합니다.
- 앨범명과 선택적인 아티스트로 MusicBrainz의 앨범 그룹을 검색하고, 최대 8개 결과를 확인한 뒤 적용합니다. 한 글자 앨범은 아티스트를 함께 입력해 검색합니다. 기존 제목·아티스트·발매일·링크·감상은 유지하고 빈 정보만 채웁니다.
- 카탈로그의 날짜는 최초 발매 정보이며 사용자가 기록한 CD·LP 등 판본의 날짜와 다를 수 있습니다. 연도, 연월, 전체 날짜를 구분해 보존합니다.
- 표지는 Cover Art Archive의 공식 경로를 사용합니다. 표지가 없거나 이미지 조회가 실패하면 기본 음반 그림을 표시하며, 원본 정보 링크와 확인일을 제공합니다.
- 검색·상태·포맷 필터, 최근 등록순·앨범명순·아티스트순·별점순·감상일순 정렬을 제공합니다. 평균 별점은 직접 평가한 앨범만 포함하고 0점과 미평가를 구분합니다.
- 인증 후 고정 MusicBrainz 주소만 요청하며, 식별 User-Agent·검색 간격 제한·24시간 공개 메타데이터 캐시·응답 크기 제한을 사용합니다. 개인 신원·쿠키·감상은 원본 서비스나 공개 캐시에 넣지 않습니다. 제공자 오류는 빈 검색 결과로 표시하지 않습니다.
- 기존 앨범에 선택적인 music 상세만 추가하며, 사용자별 저장·충돌 사본·오프라인 복구·백업을 그대로 사용합니다. DB 마이그레이션은 추가하지 않습니다.
- 카탈로그는 핵심 공개 정보만 저장합니다. 감상·장르·별점은 직접 기록합니다. 다른 음악 계정 연동과 가사 수집은 포함하지 않습니다. Spotify 계정 기능은 아래 별도 설명을 참조하세요.

## Spotify 연결 · 즐겨찾는 플레이리스트 · 감상 기록

- 음악 화면의 ‘앨범 컬렉션 / 플레이리스트 / 감상 기록’에서 사용합니다. 앨범 추가·수정 또는 플레이리스트 추가에서 Spotify의 **공유 → 링크 복사** 주소를 붙여넣고, ‘연결 정보 확인 → 적용 → 저장하기’를 누릅니다.
- Spotify 공식 oEmbed로 공개 제목·표지를 확인합니다. 제목은 빈 경우에만 채우고 기존 제목·아티스트·감상을 덮어쓰지 않습니다. Spotify 공유 URL의 추적값을 제거하며 앨범·플레이리스트 URL 및 URI만 허용합니다. 단축 링크는 전체 링크로 바꿔 입력해야 합니다.
- 상세 창에서 Spotify 재생기를 열거나 Spotify로 이동할 수 있습니다. 재생기는 클릭할 때만 로드하며 실제 재생 범위는 Spotify의 로그인·지역·계정 조건에 따릅니다. 재생을 감상 완료로 자동 기록하지 않습니다.
- 플레이리스트는 추가할 때 HUB 즐겨찾기에 등록합니다. 하트로 등록·해제하고 ‘즐겨찾기만 보기’를 끄면 전체 등록 목록을 봅니다. Spotify 계정의 보관함·팔로우 상태를 변경하지 않습니다.
- 각 앨범·플레이리스트의 ‘감상 남기기’ 또는 전체 감상 기록 탭에서 날짜·곡·청음 장비/환경·반점 별점·최대 3,000자 메모를 추가·수정·삭제합니다. 항목당 최대 200개, 최근 감상순이며 검색할 수 있습니다. 최근 감상일은 직접 입력한 날짜와 감상 기록 중 최신 날짜입니다.
- 같은 사용자별 JSON 문서로 저장하므로 다른 기기 동기화·오프라인 보류·충돌 사본·백업 왕복을 지원합니다. 기존 앨범 기록과 MusicBrainz 연결을 보존하며 추가 SQL 마이그레이션은 없습니다. 문서 전체 1MB 제한이 적용됩니다.
- 공유 링크 기능은 계정 인증 없이 사용할 수 있습니다. Spotify Premium 계정의 OAuth·실시간 재생·라이브러리는 아래 계정 연결 기능과 별도의 상세 음악 페이지에서 제공합니다. 비공개·삭제된·지원되지 않는 항목은 정보 조회나 재생에 실패할 수 있습니다.
- 제공자 HTML은 렌더링하지 않고 검증한 ID로 재생기 주소를 만듭니다. 서버는 로그인 후 고정 Spotify oEmbed 주소만 요청하고 사용자 신원·쿠키·개인 감상은 Spotify에 전달하지 않습니다. 표지는 Spotify 이미지 호스트만 허용합니다.

## 홈의 이어서 하기와 통합 검색

- 홈의 ‘이어서 하기’에서 보던 작품, 현재 재생 중인 Spotify 곡 또는 최근 감상 기록, 선택한 Steam 계정의 최근 게임, 고정 청음 조합 또는 최근 감상 장비에 접근합니다. 재생 조작은 Spotify 관리 화면에서, Steam 원본 정보 갱신은 Steam 라이브러리에서 합니다.
- 홈 제목 옆 또는 **설정 → 홈 위젯**에서 작품·음악·게임·오디오와 맨시티 경기의 표시 여부를 바꿉니다. ‘하단 위젯 순서’에서는 이어서 하기·주간 일정·최근 기록·즐겨찾기·관심 뉴스의 순서를 조정합니다. 홈 위젯 설정은 계정 동기화와 백업에 포함됩니다.
- 상단 검색 또는 `Ctrl+K` / `⌘K`에서 제목·메모·분류, 음악 아티스트·태그·즐겨찾기·감상별 곡/장비/메모, 게임 태그·App ID, 장비 상세를 함께 검색합니다. 검색어가 여러 개면 모두 포함된 항목을 표시합니다.
- 전체/HUB 기록/영화·드라마·웹툰/음악/내 게임 기록/Steam 보유 게임으로 범위를 선택합니다. HUB 결과는 현재 보류 변경을 포함하고 20개씩 더 봅니다. Steam은 연결한 모든 계정의 저장된 보유 목록에서 20개씩 검색하고 계정·확인 시각·이전 조회 여부를 표시합니다. 동일 게임도 계정별로 구분하며 결과에서 해당 계정의 게임으로 이동합니다. 통합 검색은 HUB에 저장한 개인 기록과 연결 계정의 Steam 보유 목록을 대상으로 합니다.
- 새 `/api/steam/summary`, `/api/steam/search`는 로그인 사용자의 D1 스냅샷만 읽고 private/no-store로 응답합니다. 추가 OAuth 권한·환경변수·DB 마이그레이션은 없습니다.
