- RSS/Atom 처리, 발행일·URL·XML·응답 크기 검증, 소스 실패 격리 및 전부 실패 시 캐시 보존
- 중복 URL·복수 분야 병합·최초 수집 시각 보존, 동시 실행 잠금과 갱신 제한
- 분야·검색·날짜·커서, 계정별 상태 및 다른 필드 보존, 쓰기 출처 검사, 스크랩 JSON 내보내기
- TypeScript와 Next.js/Worker 빌드 통과, 빌드된 Worker의 뉴스 HTML 200
- 실제 공개 RSS 7/7 연결 및 6개 분야 기사 28개 수집 확인 (이후 재수집에 따라 축적 수는 달라짐)
- 브라우저에서 게임 분야 → 읽음·스크랩 → 새로고침 후 상태 보존 확인
- 별도 브라우저 저장소에서도 같은 스크랩 상태 표시, 390px 모바일 화면 확인

로컬 검증용 기사 상태는 `.sites-runtime/local.sqlite`에만 저장됩니다. 운영 데이터로 테스트 스크랩을 만들지 않습니다. 기사 소개는 RSS 제공문이며 AI 요약이 아닙니다. 영어 번역, 닫힌 동안의 예약 실행, 실제 아이폰 하드웨어 검증은 제공 범위에 포함하지 않았습니다.

## 0.2 · 사용자별 서버 저장

- TypeScript 검사 통과
- Next.js 화면 + Worker 번들 빌드 통과
- `node --test tests/*.test.mjs`: 18/18 통과
- 실제 SQL 마이그레이션을 적용한 SQLite에서 사용자 격리, 동시 갱신 비교, 중복 요청, CSRF·입력·크기 검증
- 독립 클라이언트 2개로 동기화, 동시 추가/수정, 오프라인 재접속, 저장 중 후속 변경, 응답 유실, 계정 변경 검증
- 여러 탭 보류 기록과 기존 브라우저 이전, 임시 저장 실패 검증
- 빌드한 Worker의 HTML 응답 200 확인
- 브라우저에서 기존 `127.0.0.1` 기록 이전 후 `localhost`의 별도 저장소에서 같은 할 일 확인
- 설정의 서버 저장 완료·기록 수·저장 시각 및 모바일 390×844 화면 확인

운영 배포는 Sites 마이그레이션을 적용합니다. 운영 DB 준비 상태는 데이터 내용 없이 확인하는 `/api/health`로 검증하고, 사용자 신원이 없는 서비스 요청은 `/api/hub`에서 401로 거부하도록 구성했습니다. 운영 사용자 데이터를 테스트로 만들지 않습니다.

실제 PC와 아이폰의 로그인 후 왕복 수정은 아직 하드웨어에서 확인하지 않았습니다. 완전한 오프라인 실행, 외부 캘린더·Steam·뉴스 API 연결은 범위 밖입니다. 아래는 0.1의 당시 검증 기록입니다.

- TypeScript 정적 검사 통과
- Next.js 프로덕션 정적 빌드 통과 (홈 + 8개 메뉴 + 오류 경로)
- `node --test tests/store.test.mjs`: 5/5 통과
- 로컬 서버 HTTP 200 확인
- 브라우저 실제 날씨 응답 확인 (Open-Meteo, 서울)
- 할 일 등록 → 완료 → 새로고침 후 상태 유지 확인
- 저장 기록을 통합 검색에서 찾는 동작 확인
- 모바일 390×844 레이아웃과 하단 내비게이션 확인
- 캘린더 날짜 클릭 후 KST 오전 9시로 일정 입력 기본값이 설정됨을 확인

동작 확인용 할 일은 localhost 브라우저에만 저장되며 배포 소스와 프로덕션 데이터에는 포함되지 않습니다. 실제 아이폰 기기, 외부 서비스 계정 연동, 클라우드 DB와 오프라인 동작은 검증 대상에 포함되지 않습니다.
