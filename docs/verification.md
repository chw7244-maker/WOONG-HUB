## 내 음원 라이브러리 저장 오류 · 2026-11-24

- 증상: 운영에서 폴더를 읽은 뒤 ‘라이브러리를 저장하지 못했어요.’가 나왔습니다. 운영 API를 읽기만 해서 확인하니 표지는 약 90장 올라가 있고 라이브러리는 비어 있었습니다. 표지 올리기는 성공하고 마지막 곡 정보 저장(PUT)이 413이 아닌 오류로 거절된 것입니다. 정확한 응답 코드는 알림에 나오지 않아 확인하지 못했습니다(운영에 시험 저장을 보내지 않았습니다).
- 원인 후보와 수정: ① 경로 검사가 ‘..’이 들어간 이름 전체를 막아 `Wait....flac`, `...And More` 같은 실제 파일·폴더 이름이 거절됐습니다. 이제 경로 조각이 정확히 `.`·`..`·빈 칸일 때만 막습니다. ② 태그 값(트랙 번호 2147483647, 디스크 1000, 연도 20230101, 빈 제목 등)이 범위를 벗어나면 곡 전체가 거절됐습니다. 이제 읽을 때 범위 밖 숫자는 비우고 제목은 파일 이름으로 채웁니다. ③ 곡이 많아도 요청 크기 제한에 걸리지 않도록 gzip으로 압축해 보냅니다(서버는 압축본 4MB · 풀린 내용 12MB까지). ④ 보내기 전에 브라우저에서 검사하고, 거절되면 그 파일 경로나 응답 코드를 알림에 보여 주며, 서버 오류는 로그에 남깁니다.
- 자동 테스트 2개(새로): 이상한 태그·이름으로 만든 곡이 저장 검사를 통과하고 `.`·`..`·빈 조각·절대 경로·역슬래시는 거절되며 거절 메시지에 경로가 나옴, gzip 저장·다시 읽기, 거절된 곡 경로가 응답 `detail`에 나옴, 깨진 gzip은 400, 13MB로 풀리는 압축본은 413. TypeScript 검사, 자동 테스트 220/220, 빌드를 통과했습니다.
- 로컬 미리보기: 예시 16곡에 `04 - Wait....flac`을 더해 폴더 읽기 → 라이브러리 저장을 하자 ‘앨범 5장, 17곡을 저장했어요’가 나오고 PUT이 200이었습니다(이전 코드라면 이 파일 때문에 거절됩니다).
- 남은 확인: 배포 후 같은 폴더로 다시 저장해 봅니다. 그래도 실패하면 알림에 나온 파일 경로나 응답 코드로 원인을 좁힙니다.

실제 PC와 아이폰의 로그인 후 왕복 수정은 아직 하드웨어에서 확인하지 않았습니다. 완전한 오프라인 실행, 외부 캘린더·Steam·뉴스 API 연결은 범위 밖입니다. 아래는 0.1의 당시 검증 기록입니다.
