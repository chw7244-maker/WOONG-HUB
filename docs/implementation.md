# 구현 기록 · 2026-11-17

## 0.5 · Notion·Google 캘린더 수동 반영

- 사용자는 노션 4개 출처를 선택한 뒤 구글 일정도 포함하고 출처별 켜기·끄기를 요청했습니다. 자동 실행은 명시적으로 선택하지 않았습니다. 실제 원본 조회는 연결된 Notion Calendar 도구를 사용하며 Google과 Notion provider를 구분합니다.
- Sites의 웹사이트 앱 연결 적합성 조회 도구가 제공되지 않아 런타임 앱 바인딩을 추측하지 않았습니다. 대신 사용자 요청 시 읽은 자료를 기존 소유자 전용 Site 서비스 접근으로 반영하는 수동 경로를 구현했습니다. 별도 API 키나 OAuth 자격 증명을 만들지 않았습니다.
- 0002 SQL은 반영본 테이블 하나만 추가합니다. 적용된 기존 SQL은 변경하지 않았습니다. 캘린더 표시 설정은 기존 사용자별 HUB 문서의 선택적 preferences.calendarHiddenSources에 보관합니다.
- 실제 출처 ID와 일정은 서버 DB에만 저장합니다. 공유 자료 writer는 Site의 소유자 전용 서비스 경계를 전제로 하며, 브라우저 출처 헤더가 있는 쓰기는 거부합니다. 일반 조회 API는 서명된 사용자 신원이 필요합니다.
- JSON 크기·출처·URL·기간·중복 검증, revision 비교, 중복 요청과 오래된 반영 거부, 읽기 재확인을 적용합니다. 실패하면 이전 반영본을 보존합니다.
- 종일 종료일 미포함, KST 자정과 0분 일정, 여러 날에 걸친 일정, 외부 반영 기간 안내를 추가했습니다. 일정 입력도 폼의 날짜 값을 직접 제출해 브라우저 날짜 이벤트 차이에 대응합니다.

## 0.4 · 오디오 장비 상세와 청음 조합

- 기존 사용자별 JSON 문서의 오디오 기록에 선택적 `audio` 필드를 추가했습니다. 이전 기록은 변환 없이 보존하며, 상세를 수정한 장비부터 구조화된 정보를 저장합니다.
- 장비 제조사·모델·구매일·원화 구매가·연결·출력·소리 성향과 기존 메모를 별도로 편집합니다. 정수 금액, 날짜, 길이, 필드 종류를 서버에서도 검증합니다.
- 청음 조합은 같은 오디오 종류의 기록이지만 `audio.type: setup`으로 구분합니다. 장비 ID 1~12개와 연결 순서를 보존하며, 삭제된 장비의 참조는 명시적으로 표시합니다.
- 같은 저장 경로를 사용해 백업, 계정 격리, 오프라인 복구와 동시 변경 사본 보존을 그대로 적용합니다. SQL 마이그레이션은 추가하지 않았습니다.
- 기존 공통 편집창을 재사용 가능한 Dialog로 분리했습니다. 오디오의 검색 결과에서 수정해도 새 상세 필드가 유실되지 않도록 오디오 전용 폼으로 연결합니다.
- Google Calendar 연결은 Sites의 플러그인 적합성 조회 도구가 현재 세션에 제공되지 않아 연결 권한을 확인할 수 없습니다. 기존 연결 전 상태를 유지하고, 외부 연결 없이 완성할 수 있는 다음 오디오 단계를 진행했습니다.
- GitHub 저장소는 사용자가 지정한 chw7244-maker/WOONG-HUB이며, 기존 초기 커밋과 Sites 소스 이력을 보존합니다.

## 0.3 · 기존 뉴스 사이트를 사용하지 않는 새 뉴스 허브

사용자가 기존 뉴스 사이트 통합 대신 새 뉴스 구조를 요청했습니다. 기본 바로가기, 홈 카드, 뉴스 화면과 설정 설명에서 기존 사이트 의존을 제거하고 HUB 자체 수집·저장·표시로 교체했습니다. 아래의 과거 설계나 통합 계획은 현재 구현을 지시하지 않는 역사 기록입니다.

- 매체가 공개한 RSS 7개를 직접 수집합니다. 검색형 RSS의 요청 제한과 오래된 공식 피드가 확인되어, 실제 응답 및 발행일을 검증한 소스를 선택했습니다. 국내 오디오는 오디오플래닛 페이지가 안내한 RSS 주소입니다. 영디비는 운영 Worker에서 HTTP 403을 반환해 대체했습니다.
- `0001_lyrical_mandrill.sql`은 기존 DB를 유지하면서 기사·사용자 상태·수집 상태 테이블을 추가합니다. 적용된 0000 SQL과 스냅샷은 수정하지 않았습니다.
- RSS/Atom XML을 제한된 크기로 검증하고 DTD·엔티티 선언, 잘못된 링크·발행일을 거부합니다. 기사 본문은 가져오지 않고 짧은 RSS 소개를 일반 텍스트로 표시합니다.
- 수집은 소스별 실패를 격리하고, URL 중복 제거 및 여러 분야 병합을 수행합니다. 동시 실행 잠금과 수동 갱신 간격을 둡니다.
- 기사는 서버 공통 자료이고 읽음·스크랩·숨김은 인증된 사용자 ID로 분리합니다. 쓰기는 동일 출처와 필드 검증을 거칩니다.
- 화면은 최신 기사와 분야를 분산한 상단 읽을거리, 기사 목록, 분야·날짜·검색·상태 필터와 수집 상태로 구성합니다. 모바일은 세로 기사 카드와 가로 분야 메뉴를 사용합니다.
- AI 요약·번역·예약 실행은 연결하지 않았습니다. 페이지 접속 시 1시간이 지난 경우의 갱신과 수동 갱신만 실제 제공하며 이를 UI에 설명합니다.
- 번들은 esbuild로 생성해 XML 파서와 기존 API, 정적 화면을 같은 Worker에 포함합니다. 로컬 개발 코드나 DB는 배포하지 않습니다.

검증은 `docs/verification.md`의 0.3 항목을 참고하세요.

## 0.2 · 서버 저장과 동기화

기존 소유자 전용 사이트를 유지하면서 D1 기반 사용자별 저장을 추가했습니다. 별도 Supabase 계정이나 비밀 키를 발급하지 않고, Sites의 기존 ChatGPT 로그인과 DB 바인딩을 사용합니다. 초기 설계의 데이터 동기화 요구를 충족하되 운영 환경에 맞춰 DB 구현을 변경한 결정입니다.

- Next.js 정적 화면을 유지하고 Worker API를 더했습니다. 빌드는 화면 자산을 모듈에 포함하여 기존 화면과 API를 함께 배포합니다.
- `hub_documents`의 기본 키는 플랫폼이 확인한 사용자 ID입니다. 클라이언트가 요청 본문으로 사용자를 지정할 수 없습니다.
- GET은 자신의 문서만 반환하고 PUT은 동일 출처 검사, 입력 검증, 1MB 제한, 예상 버전 비교를 수행합니다.
- 동기화 클라이언트는 브라우저 보류 기록 → 서버 확인 순서로 저장합니다. 폴링·화면 복귀·온라인 복구 시 최신 변경을 확인합니다.
- 다른 기록의 동시 변경은 병합하며, 같은 기록 동시 수정과 삭제/수정 충돌은 내용을 보존하는 쪽으로 처리합니다. 완전한 협업 편집기는 아닙니다.
- 각 탭의 보류 기록을 별도로 보관하여 다른 탭이 임시 저장 내용을 덮어쓰지 않습니다. 초기 서버 응답으로 계정을 확인한 후에만 해당 계정의 보류 기록을 복구합니다.
- 기존 `woong-hub:v1`은 삭제하지 않습니다. 사용자가 이전 버튼을 누르면 현재 서버 문서에 합치고, 서버 저장 완료 후 이전 표시를 기록합니다.
- 로컬 개발 서버와 SQLite 어댑터는 운영 Worker에 포함하지 않습니다. 마이그레이션은 스키마만 포함합니다.

검증: 18개 자동 테스트 및 브라우저에서 이전 → 서버 저장 완료 → 별도 출처의 브라우저 저장소에서 같은 할 일 확인. 실제 아이폰 하드웨어 검증은 남아 있습니다.

아래는 0.1 단계의 당시 결정과 남은 작업 기록입니다. Supabase 관련 미완료 항목은 이번 D1 구현으로 대체되었습니다.

## 결정

Next.js + React + TypeScript를 유지하고, 첫 화면 검증을 위해 정적 내보내기를 사용합니다. UI는 앱 자체의 CSS 변수 기반 컴포넌트로 구성했습니다. Tailwind 및 shadcn/ui는 현재 사용하지 않습니다. Supabase 인증·DB가 설정되지 않은 상태에서 서버 동기화를 가장하지 않고, 첫 개발 버전임을 UI 설정에 표시합니다. 저장소 모듈은 `src/lib/store.ts`에 분리했으며 후속 단계에서 서버 저장 방식으로 교체할 수 있습니다.

새 Sites는 비공개로 생성했습니다. 소유자 전용 플랫폼 접근 제한을 사용하며, 공개 배포나 공유 권한 변경은 수행하지 않습니다. Supabase 로그인은 별도의 다음 단계입니다.
