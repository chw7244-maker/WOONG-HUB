# WOONG HUB

취미와 일상을 기록하는 개인 대시보드. **0.8 버전은 Spotify 앨범·플레이리스트 링크 연결, 플레이리스트 즐겨찾기, 날짜별 감상 기록**을 제공합니다. 게임 라이브러리, 통합 캘린더, 오디오 상세·청음 조합, 독립 RSS 뉴스와 사용자별 서버 저장·동기화도 함께 사용합니다.

## 실행

Node.js 24 이상, pnpm 11.25.0을 사용합니다. 미리보기는 운영 DB와 분리된 SQLite DB를 사용합니다.

```powershell
pnpm install
pnpm check
pnpm test
pnpm build
pnpm preview
```

`http://127.0.0.1:3000`에서 확인합니다. `pnpm dev`도 같은 빌드 결과를 제공하며 변경 후에는 다시 빌드해야 합니다. 개발 서버가 넣는 `local-preview-owner`는 로컬에서만 사용하고 배포 파일에 포함하지 않습니다. DB와 테스트 기록은 무시된 `.sites-runtime/local.sqlite`에 있습니다.

화면은 Next.js App Router + React + TypeScript이며 `out/`으로 내보냅니다. 빌드 스크립트가 화면 자산과 API를 하나의 Cloudflare Worker 모듈인 `dist/server/index.js`로 묶습니다. Sites의 기존 프로젝트 ID와 소유자 전용 접근을 유지하며, `.openai/hosting.json`의 `d1: "DB"`로 운영 DB를 연결합니다. 이 버전부터 정적 전용 배포로는 API가 작동하지 않습니다.

- 반응형 홈, PC 사이드바, 모바일 하단 내비게이션

- 서울 기본값 및 도시 선택, Open-Meteo 날씨 조회와 실패/재시도 화면
- 한국 시간대 날짜, 월 이동 캘린더, 직접 일정 등록
- 할 일·메모·북마크·오디오·게임·앨범·업무 기록 추가/수정/삭제
- 통합 검색, 할 일 완료 처리, 일정 알림 목록
- 로그인 계정별 서버 저장, 15초 간격 및 화면 복귀 시 동기화
- 동시 변경 버전 검사와 충돌 시 사본 보존
- 기기별·탭별 보류 변경 보관, 오프라인 변경 재전송, 저장 상태 표시
- 이전 브라우저 기록의 병합 이전 및 원본 보존
- 검증을 거친 JSON 가져오기/내보내기
- 독립 뉴스 허브, 분야·검색·날짜 필터, 읽음·스크랩·숨김과 계정별 저장
- 홈의 실제 기사 미리보기, IEM Atlas·스토어 인사이트 바로가기
- 모바일 설치용 웹 앱 매니페스트 (오프라인 실행과 푸시는 미구현)

## 저장과 연결 상태

기록과 설정은 **Sites D1 DB의 사용자별 문서**에 저장합니다. 기존 ChatGPT 로그인을 사용하며 별도 Supabase 계정이나 API 키는 필요하지 않습니다. API는 플랫폼이 주입한 사용자 ID로만 문서를 읽고, 쓰기 요청은 동일 출처와 JSON 형식을 검사합니다.

한 번의 저장은 사용자별 문서 전체에 대해 버전을 비교하고 갱신합니다. 다른 기기의 변경이 먼저 저장되면 최신 문서를 받아 세 방향으로 합칩니다. 서로 다른 기록은 합쳐지고, 동일 기록 동시 수정은 사본으로 남깁니다. 삭제와 수정이 충돌하면 수정 내용을 우선 보존하므로 사용자가 사본을 확인해야 할 수 있습니다. 첫 버전의 문서 크기는 사용자당 1MB로 제한합니다.

화면에서 변경하면 먼저 계정·탭별 보류 기록을 브라우저에 보관하고 서버 저장을 확인합니다. ‘서버 저장 완료’ 전에는 브라우저 데이터를 지우지 마세요. 오프라인 최초 접속이나 완전한 오프라인 앱 실행은 제공하지 않습니다. 재접속하면 남은 보류 기록을 복구합니다. 서버 저장이 완료된 기록은 기기 캐시를 지워도 다시 로그인해 불러올 수 있습니다.

이전 `woong-hub:v1` 데이터가 있으면 ‘이전 기록 백업’과 ‘서버로 옮기기’를 표시합니다. 이전 원본을 삭제하지 않으며, 현재 서버 기록과 합쳐 옮깁니다. JSON 백업 내보내기는 현재 화면의 보류 변경도 포함합니다. 파일 가져오기는 현재 기록을 교체하므로 확인 창을 제공합니다.

DB 스키마는 `db/schema.ts`, 생성된 마이그레이션은 `drizzle/`에 보관합니다. 스키마 변경 시 `pnpm db:generate`로 새 SQL을 생성하고 검토합니다. 로컬 미리보기는 시작 시 미적용 SQL만 적용하고, 운영 마이그레이션은 Sites 배포가 적용합니다. 사용자 데이터는 SQL 마이그레이션에 넣지 않습니다.

Steam 계정, AI 요약, 사이트가 닫혀 있을 때의 예약 실행, 가격 알림은 연결되지 않았습니다. 캘린더는 아래 설명처럼 요청 시 반영하며 웹사이트가 원본 제공자에 실시간 접속하지 않습니다. 테스트용 기사·날씨·보유 장비를 실제 개인 데이터처럼 생성하지 않습니다. 날씨는 브라우저에서 API에 직접 요청하며 네트워크 상황이나 제공자 제한에 따라 실패할 수 있습니다. 폰트 실패 시 시스템 한국어 글꼴로 대체됩니다.

## 새 뉴스 허브

- 6개 분야: 오디오·음악 / 게임 / PC·IT / 국내 오디오 / 국내 이슈 / 해외
- 공개 RSS 7개: Headfonia, Pitchfork, PC Gamer, Ars Technica, 오디오플래닛, 연합뉴스, BBC News
- 허용된 소스 주소만 서버에서 요청하며 사용자가 전달한 URL을 수집하지 않습니다.
- 처음 접속하거나 마지막 확인 후 1시간이 지나면 새 기사를 수집합니다. 페이지가 열려 있을 때의 갱신이며, 닫힌 동안 실행되는 예약 작업은 만들지 않았습니다.
- 수동 ‘새 기사 확인’은 60초 간격 제한과 동시 실행 잠금을 적용합니다. 일부 매체가 실패해도 저장된 기사와 다른 소스의 결과는 유지됩니다.
- 소스당 최근 90일 이내 항목 중 최신 4개씩 가져오며, URL의 추적 정보를 정리하고 중복을 제거합니다. 축적된 기사는 DB에 남고 날짜·검색·분야·읽기 상태로 찾을 수 있습니다.
- RSS 제목·발행일·매체가 제공한 짧은 소개(최대 240자)·원문 링크만 저장합니다. 기사 본문을 크롤링하지 않습니다. 소개는 AI 요약이 아니며 영어 기사는 원문 언어로 표시합니다.
- `news_articles`는 기사 자료, `news_user_states`는 계정별 읽음·스크랩·숨김, `news_sync`는 수집 잠금과 상태입니다. 기존 개인 기록 문서와 분리했습니다.
- 뉴스 상태는 온라인 API로 저장합니다. 저장 실패 시 표시를 되돌리고 오류를 안내합니다. 개인 기록의 오프라인 보류 저장 기능과는 다릅니다.
- ‘스크랩 백업’은 저장 기사를 별도 JSON으로 내보냅니다(최신 1,000개, 전체 수 및 초과 여부 포함). 기존 HUB JSON 백업은 개인 기록·설정용이며 뉴스 상태는 포함하지 않습니다.
- 출처별 RSS 제공 범위·일시 오류·날짜 누락에 따라 기사 수가 달라집니다. 연결 결과와 마지막 성공 시각을 화면에서 확인할 수 있습니다.

## Notion · Google 캘린더

- 사용자가 고른 Notion 캘린더와 Google 캘린더를 원본 수정 없이 읽기 전용으로 반영합니다. 자동 작업은 만들지 않으며, 이 채팅에 ‘캘린더 일정 다시 반영해줘’라고 요청하면 갱신합니다.
- 월간 달력, 날짜별 일정, 종일·기간·시간 지정 일정, KST 표시와 원본 열기를 제공합니다. 직접 등록한 HUB 일정도 함께 표시합니다.
- 출처별 스위치와 모두 켜기·끄기로 표시를 선택합니다. 설정은 계정별로 동기화하고 백업에 포함합니다. 표시를 꺼도 반영본과 원본 일정은 삭제하지 않습니다.
- 홈에도 같은 표시 설정과 다가오는 일정을 적용합니다. 외부 반영본의 마지막 반영 시각과 조회 기간을 표시하며, 기간 밖에는 누락 가능성을 안내합니다.
- ‘반영 내역 새로고침’은 저장된 반영본을 다시 읽습니다. 웹사이트가 제공자의 새 일정을 직접 조회하거나 자동 동기화하는 기능은 아닙니다.
- 캘린더 자료는 소유자 전용 Site의 서버 반영본으로 보관합니다. 소스·공개 GitHub·빌드 산출물에는 실제 일정이나 출처 ID를 넣지 않습니다. 개인 HUB 백업은 표시 설정과 직접 일정만 포함하고 외부 반영본은 포함하지 않습니다.
- 운영 반영 절차는 docs/calendar-update.md에 있습니다. Site를 다른 사람에게 공유하거나 공개하기 전에 반영본의 접근 설계를 다시 확인해야 합니다.

## 오디오 컬렉션과 청음 조합

- 장비 이름, 분류·상태, 제조사·모델, 구매일·구매가(원), 연결·출력, 소리 성향, 청음·사용 메모를 기록합니다.
- 장비와 조합을 별도 목록으로 보고 검색·분류·상태 필터, 최근 등록순·이름순 정렬을 사용합니다.
- 조합은 등록 장비 1~12개를 선택하고 위·아래 버튼으로 연결 순서를 정합니다. 전기적 호환성을 자동 판단하지 않습니다.
- 장비 삭제 시 조합을 함께 삭제하지 않습니다. 남은 연결은 찾을 수 없는 장비로 표시하고 조합 수정에서 바꿀 수 있습니다.
- 보유 구매가 합계는 구매가를 직접 기록한 보유 장비만 포함하며, 가격 입력 수를 함께 표시합니다. 미입력과 0원은 다르게 처리합니다.
- 기존 장비 메모를 유지하고 선택적 `audio` 상세 필드만 더합니다. 기존 JSON 문서와 같은 사용자별 저장·충돌 보존·오프라인 보류·백업을 사용하며 추가 DB 마이그레이션은 없습니다.
- 제품 사양, 가격, 보유 장비를 외부에서 자동 생성하지 않습니다. 새 컬렉션은 빈 상태로 시작합니다.

## 게임 라이브러리와 Steam 상점 정보

- 게임별 플랫폼·상태, 직접 기록한 플레이 시간, 0~5점 별점(0.5점 단위), 시작일·완료일, 최대 8개 태그와 감상 메모를 보관합니다.
- Steam 상점 URL 또는 App ID를 입력해 제목·제작사·배급사·장르·출시 표시·짧은 소개·커버를 확인한 뒤 적용합니다. 기존 제목·관련 링크·메모를 유지하고 빈 제목과 링크만 채웁니다. 저장 전 미리보기를 제공합니다.
- 상점 정보는 게임·DLC 공개 응답만 사용합니다. Steam 계정 로그인·보유 게임·자동 플레이 시간 연결이나 가격 조회는 포함하지 않습니다. 상점 조회가 실패해도 직접 입력할 수 있습니다.
- 서버는 고정 Steam 상점 주소만 요청하고 인증된 방문자에게만 결과를 반환합니다. 공개 메타데이터만 최대 24시간 캐시하며, 확인일을 표시합니다. 개인 기록·쿠키·사용자 신원은 Steam이나 공개 캐시에 전달하지 않습니다.
- 검색·플랫폼·상태 필터와 최근 등록순·이름순·플레이 시간순·별점순 정렬을 제공합니다. 미입력과 0분·0점은 구분합니다.
- 기존 게임 기록은 그대로 보존하고 선택적인 game 상세 필드만 추가합니다. 같은 사용자별 저장·충돌 사본·오프라인 복구·JSON 백업을 사용하며 추가 DB 마이그레이션은 없습니다.
- 상점 응답은 공개 조회 가능 여부와 제공자 변경·제한에 따라 실패할 수 있습니다. 마지막으로 저장한 상점 정보와 직접 기록한 플레이 내용은 유지합니다.

## 음악 컬렉션과 앨범 검색

- 앨범명·아티스트·포맷·상태, 직접 기록한 장르·발매일/연도·반점 별점·최근 감상일·좋아하는 곡·태그·감상을 저장합니다.
- 앨범명과 선택적인 아티스트로 MusicBrainz의 앨범 그룹을 검색하고, 최대 8개 결과를 확인한 뒤 적용합니다. 한 글자 앨범은 아티스트를 함께 입력해 검색합니다. 기존 제목·아티스트·발매일·링크·감상은 유지하고 빈 정보만 채웁니다.
- 카탈로그의 날짜는 최초 발매 정보이며 사용자가 기록한 CD·LP 등 판본의 날짜와 다를 수 있습니다. 연도, 연월, 전체 날짜를 구분해 보존합니다.
- 표지는 Cover Art Archive의 공식 경로를 사용합니다. 표지가 없거나 이미지 조회가 실패하면 기본 음반 그림을 표시하며, 원본 정보 링크와 확인일을 제공합니다.
- 검색·상태·포맷 필터, 최근 등록순·앨범명순·아티스트순·별점순·감상일순 정렬을 제공합니다. 평균 별점은 직접 평가한 앨범만 포함하고 0점과 미평가를 구분합니다.
- 인증 후 고정 MusicBrainz 주소만 요청하며, 식별 User-Agent·검색 간격 제한·24시간 공개 메타데이터 캐시·응답 크기 제한을 사용합니다. 개인 신원·쿠키·감상은 원본 서비스나 공개 캐시에 넣지 않습니다. 제공자 오류는 빈 검색 결과로 표시하지 않습니다.
- 기존 앨범에 선택적인 music 상세만 추가하며, 사용자별 저장·충돌 사본·오프라인 복구·백업을 그대로 사용합니다. DB 마이그레이션은 추가하지 않습니다.
- 카탈로그는 핵심 공개 정보만 저장합니다. 감상·장르·별점은 직접 기록합니다. Spotify나 다른 음악 계정의 보관함·재생 이력 조회, 재생 제어, 전체 트랙 목록·가사 수집은 포함하지 않습니다.

## Spotify 연결 · 즐겨찾는 플레이리스트 · 감상 기록

- 음악 화면의 ‘앨범 컬렉션 / 플레이리스트 / 감상 기록’에서 사용합니다. 앨범 추가·수정 또는 플레이리스트 추가에서 Spotify의 **공유 → 링크 복사** 주소를 붙여넣고, ‘연결 정보 확인 → 적용 → 저장하기’를 누릅니다.
- Spotify 공식 oEmbed로 공개 제목·표지를 확인합니다. 제목은 빈 경우에만 채우고 기존 제목·아티스트·감상을 덮어쓰지 않습니다. Spotify 공유 URL의 추적값을 제거하며 앨범·플레이리스트 URL 및 URI만 허용합니다. 단축 링크는 전체 링크로 바꿔 입력해야 합니다.
- 상세 창에서 Spotify 재생기를 열거나 Spotify로 이동할 수 있습니다. 재생기는 클릭할 때만 로드하며 실제 재생 범위는 Spotify의 로그인·지역·계정 조건에 따릅니다. 재생을 감상 완료로 자동 기록하지 않습니다.
- 플레이리스트는 추가할 때 HUB 즐겨찾기에 등록합니다. 하트로 등록·해제하고 ‘즐겨찾기만 보기’를 끄면 전체 등록 목록을 봅니다. Spotify 계정의 보관함·팔로우 상태를 변경하지 않습니다.
- 각 앨범·플레이리스트의 ‘감상 남기기’ 또는 전체 감상 기록 탭에서 날짜·곡·청음 장비/환경·반점 별점·최대 3,000자 메모를 추가·수정·삭제합니다. 항목당 최대 200개, 최근 감상순이며 검색할 수 있습니다. 최근 감상일은 직접 입력한 날짜와 감상 기록 중 최신 날짜입니다.
- 같은 사용자별 JSON 문서로 저장하므로 다른 기기 동기화·오프라인 보류·충돌 사본·백업 왕복을 지원합니다. 기존 앨범 기록과 MusicBrainz 연결을 보존하며 추가 SQL 마이그레이션은 없습니다. 문서 전체 1MB 제한이 적용됩니다.
- 이 버전은 **공유 링크 연결**입니다. 사이트의 앱 연동 적합성 조회 도구가 없어 Spotify 계정 OAuth·보관함 자동 가져오기·최근 재생 이력 자동 수집은 구현하지 않았습니다. 비공개·삭제된·지원되지 않는 항목은 정보 조회나 재생에 실패할 수 있습니다.
- 제공자 HTML은 렌더링하지 않고 검증한 ID로 재생기 주소를 만듭니다. 서버는 로그인 후 고정 Spotify oEmbed 주소만 요청하고 사용자 신원·쿠키·개인 감상은 Spotify에 전달하지 않습니다. 표지는 Spotify 이미지 호스트만 허용합니다.
