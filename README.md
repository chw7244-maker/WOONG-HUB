# WOONG HUB

취미와 일상을 기록하는 개인 대시보드. **0.3 버전은 기존 뉴스 사이트를 사용하지 않고, 매체 RSS를 직접 수집하는 독립 뉴스 허브**를 제공합니다. 0.2의 사용자별 서버 저장·기기 간 동기화도 함께 사용합니다.

## 실행

Node.js 24 이상, pnpm 11.25.0을 사용합니다. 미리보기는 운영 DB와 분리된 SQLite DB를 사용합니다.

```powershell
pnpm install
pnpm check
pnpm test
pnpm build
pnpm preview
```

`http://127.0.0.1:3000`에서 확인합니다. `pnpm dev`도 같은 빌드 결과를 제공하며 변경 후에는 다시 빌드해야 합니다. 개발 서버가 넣는 `local-preview-owner`는 로컬에서만 사용하고 배포 파일에 포함하지 않습니다. DB와 테스트 기록은 무시된 `.sites-runtime/local.sqlite`에 있습니다.

화면은 Next.js App Router + React + TypeScript이며 `out/`으로 내보냅니다. 빌드 스크립트가 화면 자산과 API를 하나의 Cloudflare Worker 모듈인 `dist/server/index.js`로 묶습니다. Sites의 기존 프로젝트 ID와 소유자 전용 접근을 유지하며, `.openai/hosting.json`의 `d1: "DB"`로 운영 DB를 연결합니다. 이 버전부터 정적 전용 배포로는 API가 작동하지 않습니다.

- 반응형 홈, PC 사이드바, 모바일 하단 내비게이션

- 서울 기본값 및 도시 선택, Open-Meteo 날씨 조회와 실패/재시도 화면
- 한국 시간대 날짜, 월 이동 캘린더, 직접 일정 등록
- 할 일·메모·북마크·오디오·게임·앨범·업무 기록 추가/수정/삭제
- 통합 검색, 할 일 완료 처리, 일정 알림 목록
- 로그인 계정별 서버 저장, 15초 간격 및 화면 복귀 시 동기화
- 동시 변경 버전 검사와 충돌 시 사본 보존
- 기기별·탭별 보류 변경 보관, 오프라인 변경 재전송, 저장 상태 표시
- 이전 브라우저 기록의 병합 이전 및 원본 보존
- 검증을 거친 JSON 가져오기/내보내기
- 독립 뉴스 허브, 분야·검색·날짜 필터, 읽음·스크랩·숨김과 계정별 저장
- 홈의 실제 기사 미리보기, IEM Atlas·스토어 인사이트 바로가기
- 모바일 설치용 웹 앱 매니페스트 (오프라인 실행과 푸시는 미구현)

## 저장과 연결 상태

기록과 설정은 **Sites D1 DB의 사용자별 문서**에 저장합니다. 기존 ChatGPT 로그인을 사용하며 별도 Supabase 계정이나 API 키는 필요하지 않습니다. API는 플랫폼이 주입한 사용자 ID로만 문서를 읽고, 쓰기 요청은 동일 출처와 JSON 형식을 검사합니다.

한 번의 저장은 사용자별 문서 전체에 대해 버전을 비교하고 갱신합니다. 다른 기기의 변경이 먼저 저장되면 최신 문서를 받아 세 방향으로 합칩니다. 서로 다른 기록은 합쳐지고, 동일 기록 동시 수정은 사본으로 남깁니다. 삭제와 수정이 충돌하면 수정 내용을 우선 보존하므로 사용자가 사본을 확인해야 할 수 있습니다. 첫 버전의 문서 크기는 사용자당 1MB로 제한합니다.

화면에서 변경하면 먼저 계정·탭별 보류 기록을 브라우저에 보관하고 서버 저장을 확인합니다. ‘서버 저장 완료’ 전에는 브라우저 데이터를 지우지 마세요. 오프라인 최초 접속이나 완전한 오프라인 앱 실행은 제공하지 않습니다. 재접속하면 남은 보류 기록을 복구합니다. 서버 저장이 완료된 기록은 기기 캐시를 지워도 다시 로그인해 불러올 수 있습니다.

이전 `woong-hub:v1` 데이터가 있으면 ‘이전 기록 백업’과 ‘서버로 옮기기’를 표시합니다. 이전 원본을 삭제하지 않으며, 현재 서버 기록과 합쳐 옮깁니다. JSON 백업 내보내기는 현재 화면의 보류 변경도 포함합니다. 파일 가져오기는 현재 기록을 교체하므로 확인 창을 제공합니다.

DB 스키마는 `db/schema.ts`, 생성된 마이그레이션은 `drizzle/`에 보관합니다. 스키마 변경 시 `pnpm db:generate`로 새 SQL을 생성하고 검토합니다. 로컬 미리보기는 시작 시 미적용 SQL만 적용하고, 운영 마이그레이션은 Sites 배포가 적용합니다. 사용자 데이터는 SQL 마이그레이션에 넣지 않습니다.

Google Calendar OAuth, Steam 계정, AI 요약, 사이트가 닫혀 있을 때의 예약 실행, 가격 알림은 연결되지 않았습니다. 테스트용 기사·날씨·보유 장비를 실제 개인 데이터처럼 생성하지 않습니다. 날씨는 브라우저에서 API에 직접 요청하며 네트워크 상황이나 제공자 제한에 따라 실패할 수 있습니다. 폰트 실패 시 시스템 한국어 글꼴로 대체됩니다.

## 새 뉴스 허브

- 6개 분야: 오디오·음악 / 게임 / PC·IT / 국내 오디오 / 국내 이슈 / 해외
- 공개 RSS 7개: Headfonia, Pitchfork, PC Gamer, Ars Technica, 영디비, 연합뉴스, BBC News
- 허용된 소스 주소만 서버에서 요청하며 사용자가 전달한 URL을 수집하지 않습니다.
- 처음 접속하거나 마지막 확인 후 1시간이 지나면 새 기사를 수집합니다. 페이지가 열려 있을 때의 갱신이며, 닫힌 동안 실행되는 예약 작업은 만들지 않았습니다.
- 수동 ‘새 기사 확인’은 60초 간격 제한과 동시 실행 잠금을 적용합니다. 일부 매체가 실패해도 저장된 기사와 다른 소스의 결과는 유지됩니다.
- 소스당 최근 90일 이내 항목 중 최신 4개씩 가져오며, URL의 추적 정보를 정리하고 중복을 제거합니다. 축적된 기사는 DB에 남고 날짜·검색·분야·읽기 상태로 찾을 수 있습니다.
- RSS 제목·발행일·매체가 제공한 짧은 소개(최대 240자)·원문 링크만 저장합니다. 기사 본문을 크롤링하지 않습니다. 소개는 AI 요약이 아니며 영어 기사는 원문 언어로 표시합니다.
- `news_articles`는 기사 자료, `news_user_states`는 계정별 읽음·스크랩·숨김, `news_sync`는 수집 잠금과 상태입니다. 기존 개인 기록 문서와 분리했습니다.
- 뉴스 상태는 온라인 API로 저장합니다. 저장 실패 시 표시를 되돌리고 오류를 안내합니다. 개인 기록의 오프라인 보류 저장 기능과는 다릅니다.
- ‘스크랩 백업’은 저장 기사를 별도 JSON으로 내보냅니다(최신 1,000개, 전체 수 및 초과 여부 포함). 기존 HUB JSON 백업은 개인 기록·설정용이며 뉴스 상태는 포함하지 않습니다.
- 출처별 RSS 제공 범위·일시 오류·날짜 누락에 따라 기사 수가 달라집니다. 연결 결과와 마지막 성공 시각을 화면에서 확인할 수 있습니다.
