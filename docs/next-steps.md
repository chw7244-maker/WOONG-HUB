## 1단계 배포 후 확인할 것

2026-11-23 운영에서 아래 세 가지를 확인했습니다. 결과는 [검증 기록](verification.md)에 있습니다.

- **오디오:** 운영의 장비 43개 중 ‘케이블 · 이어팁’ 18개를 **이어팁 · 케이블로 나누기**로 나눌 때 추측이 맞는지 봅니다. 로컬 시험에서는 AZLA Mithril처럼 이름만으로 정할 수 없는 것이 ‘그대로 두기’로 남았습니다. 적용 전에는 바뀌지 않으므로, 틀린 추측은 창에서 고친 뒤 적용합니다.
- **축구:** 운영 서버에서 로고가 받아지는지 봅니다. 첫 방문에 일부가 약칭으로 나오면 새로고침 뒤 다시 봅니다. 실패한 로고는 503으로 돌려 캐시하지 않습니다. 로고 출처는 `worker/football.mjs`의 `crestOverrides`(열리지 않는 OpenLigaDB 주소를 대신하는 Wikimedia 파일)와 `crestHosts`(허용 출처)입니다. 승격 팀이 바뀌어 로고가 안 나오면 이 두 곳을 봅니다.
- **게임:** Steam에 연결된 게임이 ‘Steam ○시간’으로, Steam 0분인 게임에 직접 적은 시간이 있으면 ‘직접 ○시간’으로 나오는지 봅니다.

## 2단계 · 게임 목록 개편

대상 파일: `src/components/games-hub.tsx`, `games.css`, `src/lib/games.ts`. 별점 부품(`InlineStars`, `RatingSheet`)은 지금은 `games-hub.tsx` 안에 있습니다. 음악·작품에도 쓰게 되면 따로 파일로 옮깁니다.

**한 일 (2026-11-23):** 아래 내용을 모두 만들었습니다. 바로 추가 입력칸은 3단계에서 만들기로 하고 이번에는 넣지 않았습니다. 결과는 [검증 기록](verification.md)에 있습니다.

- **보기 전환:** 지금의 ‘목록 / 카드’를 ‘목록 / 표지’로 바꿉니다. 상태 탭과 묶어 보기 선택은 전환해도 유지하고, 마지막 보기는 지금처럼 기기별로 기억합니다(`woong-hub:games-view`). 표지 보기는 위에 ‘다음에 할 게임’(플레이 예정 중 최근 것) 큰 카드, 아래에 묶음별 선반입니다. 표지에는 별점 배지를 붙입니다. 두 화면의 위쪽(바로 추가 입력칸, 상태 탭, 묶어 보기, 전환 버튼)은 같게 합니다.
- **목록 한 줄:** 커버 · 제목(최대 340px) · 플레이 시간 · 별 5개 · 상태 · 한 줄 메모(남는 폭 전부) · 더보기 순서입니다. 제목과 시간 사이를 벌리지 않습니다(시안 댓글). 태블릿 이하에서는 한 줄 메모 칸부터 숨깁니다.
- **별점 바로 수정 (PC):** 별을 누르면 바로 저장하고 ‘되돌리기’ 알림을 띄웁니다. 같은 별을 다시 누르면 0.5점이 빠집니다(4 → 3.5). 0.5점 단위를 유지합니다.
- **별점 팝업 (휴대폰):** 행의 별점 버튼을 누르면 아래에서 창이 올라옵니다. 큰 별 5개가 놓인 띠를 손가락으로 쓸면 위치까지 0.5점 단위로 채워집니다(최소 0.5). 탭만 해도 별의 왼쪽 절반은 반 점, 오른쪽 절반은 한 점입니다. 키보드는 화살표로 0.5점씩 움직입니다. ‘별점 지우기’와 ‘○점으로 저장’ 버튼이 있습니다. 슬라이드 바는 쓰지 않습니다(시안 댓글).
- **묶어 보기:** 별점(★4.5–5, ★4, ★3–3.5, ★2.5 이하, 아직 별점 없음) · 장르(Steam 상점 장르, 없으면 ‘장르 미기록’) · 상태 · 플랫폼. 묶음 안은 별점 높은 순, 같으면 제목순입니다.
- **한 줄 메모:** 메모가 없으면 ‘+ 한 줄 메모’ 칸을 보여주고, 누르면 그 자리에서 입력해 Enter로 저장합니다. **정한 것:** 새 필드를 두지 않고 기존 감상 메모(`entry.detail`)의 첫 줄을 씁니다. 목록에서 고치면 첫 줄만 바뀌고 나머지 줄은 그대로 남습니다(`withMemoLine`). 저장 형식이 그대로라 백업·병합은 바뀌지 않습니다.
- **같은 부품 재사용:** 음악은 이미 0.5점 단위(`music.rating`)라 그대로 씁니다. 작품은 지금 정수 0~5(`watch.rating`, `src/lib/watch.ts`의 검사)라서, 0.5점을 허용할지 정한 뒤 검사와 테스트를 같이 고칩니다.

## 3단계 · 간편 추가와 Steam 찜 목록

**한 일 (2026-11-23):** 아래 계획대로 만들었습니다. 결과는 [검증 기록](verification.md)에 있습니다. 계획과 다른 점:
- 바로 추가 입력칸은 게임·작품·음악 페이지 제목 옆에 있고, 상태 탭을 따르지 않고 시안처럼 버튼 두 개(게임: 위시리스트·플레이 예정, 작품: 보는 중·볼 예정, 앨범: 위시리스트·컬렉션)를 둡니다.
- Steam 이름 검색은 실제 응답으로 확인했습니다(`storesearch`, 키 없음, 한국어 이름 검색 가능, 장르 없음). 찜 목록 조회도 키 없이 `steamid`만으로 됩니다. 여러 게임을 한 번에 주는 `IStoreBrowseService/GetItems`는 장르를 주지 않아 쓰지 않았습니다.
- 찜 목록 확인과 상점 정보 채우기는 브라우저가 `/api/games/steam`을 1.1초 간격으로 하나씩 부릅니다. 찜 목록 확인은 한 번에 30개까지 담습니다.

- **Steam 장르 채우기 (2단계 배포 후 추가):** 운영 게임 56개는 `game.steamAccount`(계정 연결, 시간)만 있고 `game.steam`(상점 정보: 장르·표지·제작사)은 없어서 장르 묶음이 모두 ‘장르 미기록’입니다. 간편 추가와 같은 상점 조회(`/api/games/steam`)로 연결된 App ID의 상점 정보를 빈 게임에만 채우는 기능을 함께 만듭니다. Steam 상점 조회는 요청이 많으면 503을 돌려주므로, 한꺼번에 56번 부르지 않고 천천히 나눠 채우는 방법을 정해야 합니다.

- **입력칸 하나로 추가:** 목록 위 입력칸에 이름을 치면 후보가 뜨고, ‘위시리스트’나 ‘플레이 예정’을 누르면 표지·장르까지 채워 저장합니다. 상태는 보고 있는 상태 탭을 따릅니다. 찾지 못하면 ‘이름으로 직접 추가’를 보여줍니다. 나머지 정보는 나중에 수정 창에서 채웁니다.
  - 게임: 지금은 Steam 주소나 App ID만 받습니다(`worker/steam.mjs`의 `appdetails`). 이름 검색은 Steam 상점의 검색 API(`store.steampowered.com/api/storesearch`)를 쓸 수 있는지 먼저 실제 응답으로 확인합니다.
  - 작품: 이미 있는 TMDB 검색(`/api/watch/search`)을 씁니다. 앨범: 이미 있는 MusicBrainz 검색(`/api/music/albums`)을 씁니다.
- **Steam 찜 목록:** Steam Web API의 찜 목록 조회(`IWishlistService/GetWishlist`, 연결한 계정의 SteamID)를 쓸 계획입니다. Steam 프로필과 찜 목록이 공개여야 하고, API 키가 필요한지는 만들 때 확인합니다. 게임 탭을 열 때 하루 한 번, 그리고 ‘지금 확인’ 버튼으로 가져옵니다. 새 게임만 ‘위시리스트’로 추가하고(App ID로 중복 확인), 찜에서 빠진 게임은 지우지 않고 표시만 합니다. 마지막 확인 시각과 새로 담은 개수를 카드에 보여줍니다.

## 4단계 · 오디오 CSV

**한 일 (2026-11-23):** 아래 내용을 만들었습니다(`src/lib/audio-csv.ts`, `src/components/audio-csv.tsx`). 결과는 [검증 기록](verification.md)에 있습니다. 계획에 더한 것:
- 내보내기는 7개 열 뒤에 모델 · 연결 · 출력 · 소리 성향 · 링크를 더 붙여, 내보낸 파일을 다시 가져와도 정보가 빠지지 않습니다.
- 한국어 엑셀이 기본으로 저장하는 EUC-KR CSV도 읽습니다(UTF-8로 읽히지 않으면 EUC-KR로 다시 읽음).
- 이름으로 분류 추측은 모델 계열 이름(HD 600, BTR, ZEN DAC, KANN 등)과 일반 낱말(헤드폰, 이어폰, 플레이어, 동글 등)로 하고, 두 분류 이상에 걸리면 추측하지 않습니다. 브랜드만으로는 추측하지 않습니다(같은 브랜드가 여러 분류를 만들기 때문).

- **가져오기:** 열은 이름 · 분류 · 제조사 · 상태 · 구매일 · 구매가 · 메모이고, 이름만 있어도 됩니다. 올리면 미리보기에서 새 장비 / 건너뜀(같은 이름이 이미 있음)을 보여주고, 분류가 비어 있으면 이름으로 추측합니다. 저장 전에 분류를 바꿀 수 있습니다.
- **내보내기:** 지금 장비를 같은 열로 내보냅니다. 엑셀에서 한글이 깨지지 않게 UTF-8 BOM을 붙입니다.
- **이름으로 분류 추측:** 지금은 이어팁·케이블만 추측합니다(`src/lib/audio.ts`의 `guessAccessory`). 이어폰·헤드폰·DAP·DAC · 앰프까지 넓혀서, 직접 추가할 때도 이름을 적으면 분류를 채웁니다.
- 완전 자동 등록은 하지 않습니다. 보유 장비를 알려주는 서비스가 없고, 쇼핑몰 주문 내역을 읽으려면 로그인이 필요하기 때문입니다(시안 댓글).

대상 파일: `src/components/hub.tsx`의 기록(`library`) 부분과 관련 CSS. 기록 종류는 메모(`note`), 할 일(`todo`), 북마크(`bookmark`)입니다.

- **무엇이든 적기:** 입력칸 하나로 종류를 정합니다. 링크가 있으면 북마크(도메인을 제목으로), ‘오늘·내일·모레·월요일~일요일·12. 1.·12월 1일’ 같은 날짜가 있으면 그 날짜의 할 일, 나머지는 메모입니다. 입력하는 동안 ‘메모로 저장 / 할 일로 저장 · 금요일 / 북마크로 저장 · 도메인’을 보여주고, 저장 뒤 종류를 바꿀 수 있게 합니다.
